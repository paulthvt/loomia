# Catch up Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** WORTH A CHECK-IN becomes CATCH UP (#342). It waits a month after someone is added to Loomia, unless they joined the team inside the app (New). It speaks up after 30 days without contact instead of 14. On mobile and tablet it shrinks to one summary line until Show is tapped, and opens on its own when nothing is due.

**Architecture:**
- **Domain:** `Person.createdAt` from `created_at` (already in the `*` select). `checkIns` gains the grace month, the 30-day quiet rule and an `added` base; `CheckInReason` gains nothing, the reason copy picks the added variant from the dates.
- **Presentation:** `checkInItems()` gains `collapsed` / `onToggle` and a summary line; `_TodayViewState` holds whether it is open.
- **No migration.**

**Tech Stack:** Flutter (`material_ui`), `flutter_riverpod` 3.

**Spec:** `docs/superpowers/specs/2026-10-15-catch-up-design.md`. Figma: section "Catch up — #342" (node `386:12036`), four mobile frames.

## Rulings made while planning

- **`createdAt` defaults to `stageSince`.** `Person` is built in 122 places, mostly tests and previews. A named `DateTime? createdAt` with the initializer `createdAt = createdAt ?? stageSince` keeps them compiling and reads as "added when they reached this stage", which is the existing fixtures' meaning. Production always reads `created_at`. Every copy in `lib` passes it on (`Person._copy`, `edit_person_form.dart`), or a local copy would lose it and turn a New member into a grace one until the next load.
- **"Reached Team inside Loomia" is `stageSince.isAfter(createdAt)`, on the timestamps.** An insert sets both from the same `now()`, so they are equal; a stage change sets `stage_since = now()` later; a backdated import or correction is earlier. Days would lose the prospect added and moved the same day.
- **Grace is checked on `added` days, not on `since`.** With nothing logged, `since` is the later of joined and added, so the 30-day quiet rule already implies the grace month. With a log older than the add day (logged with a past date), `since` is old and only the explicit grace check hides them.
- **The summary line is a card**, as in the Figma, not the bare line the spec described: it matches the rows it stands for. `Card` + `InkWell`, no new theme entry.
- **One semantics node.** The line is a button labelled with its text; the avatar group's own "N people" label is excluded so a screen reader does not say the count twice.
- **Open state is `bool?`**, null meaning "follow the default". Tapping Show or Hide sets it; it lives as long as `_TodayViewState`, like `_expanded`.
- **Tablet collapses too.** It is one column like mobile; only `isDesktop` keeps the rows open in the side column.

  - a log older than `added`, inside the grace month (`added = today − 10`, `talked = today − 90`) → empty;
  - New wins over Quiet, ordering, local calendar day: unchanged.
  `added` is set through `Person(createdAt: …)`; for "moved in the app" give `createdAt` a time before `stageSince`.
- [x] **Step 2: Implement** in `check_in.dart`:

  ```dart
  /// New for this many days after joining.
  const newForDays = 30;

  /// Nobody added to Loomia more recently than this shows: the app has had
  /// no time to see them (#342).
  const graceDays = 30;

  /// Quiet from this many days without contact.
  const quietAfterDays = 30;

  /// The day they were added to Loomia, on the device's calendar.
  DateTime addedOn(Person person) {
    final local = person.createdAt.toLocal();
    return DateTime(local.year, local.month, local.day);
  }

  /// They reached their stage after being added: the app saw them join.
  bool joinedInLoomia(Person person) =>
      person.stageSince.isAfter(person.createdAt);
  ```

  In `checkIns`: New also requires `joinedInLoomia(person)`; then `if (daysBetween(addedOn(person), today) < graceDays) continue;`; then `since = person.lastContactOn ?? (added.isAfter(joined) ? added : joined)`, Quiet when `daysBetween(since, today) >= quietAfterDays`. Update the doc comment ("new and not talked to yet, or quiet for a month, a month after they were added").
