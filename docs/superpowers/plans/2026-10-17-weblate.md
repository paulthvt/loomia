# Translations through Weblate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Gemini l10n sync with the self-hosted Weblate at https://weblate.thevenot.me/, which reads the ARB files from the repo and opens the translation pull request.

**Architecture:** Weblate (GitHub App, already installed on `paulthvt/loomia`) watches `main`, imports `lib/l10n/app_*.arb`, machine-suggests with Gemini, and pushes translations to `weblate/l10n` as a pull request. A small workflow regenerates the push copy on that branch and fixes its title. The old `translate.dart` pipeline is deleted.

**Tech Stack:** Weblate 2026.10.1 REST API (curl), GitHub Actions, Dart tool scripts, Flutter gen-l10n.

**Spec:** `docs/superpowers/specs/2026-10-16-weblate-design.md`

## Global Constraints

- Branch `chore/344-weblate` (exists, spec committed). PR body: `Closes #344`.
- Conventional Commits; PR title `chore(l10n): move translations to Weblate`.
- Weblate API key lives in `~/.config/weblate` (wlc ini). Never print it, never paste it into a file in the repo, never echo it in output.
- Every Bash call that talks to Weblate starts with:
  ```bash
  KEY=$(awk -F' = ' '/^https:\/\/weblate.thevenot.me\/api\/ =/{print $2}' ~/.config/weblate)
  B=https://weblate.thevenot.me/api
  wl() { curl -sS -H "Authorization: Token $KEY" -H "Accept: application/json" "$@"; }
  ```
- Weblate project slug `loomia`, component slug `app`, push branch `weblate/l10n`, merge style `merge`.
- French register: *tu, ton, ta, tes*, informal imperatives, never *vous, votre, vos*.
- Keep `tool/gemini.dart`, `GEMINI_API_KEY`, `tool/push_strings.dart`, `test/l10n/*`, `test/tool/push_strings_test.dart`.
- Workflow actions pinned by SHA exactly as in existing workflows (see Task 4).
- Before claiming done: `dart format .`, `flutter analyze` ("No issues found!"), `flutter test`.
- Any change on the Weblate side is outward-facing: when a step behaves differently from this plan, stop and report instead of improvising.

## Review Focus

1. **Existing French lost on import.** Creating the component must import `app_fr.arb` as translated: after Task 1, French stats show ~the same translated count as keys in `app_fr.arb`, not 0.
2. **Weblate rewrites the English base or reformats every file.** The first Weblate push must only touch translated strings: diff of `app_fr.arb` on `weblate/l10n` vs `main` is the edited strings only, `app_en.arb` untouched (Task 3 check).
3. **Workflow loop.** The workflow's own push re-triggers it; the second run must commit nothing and end (Task 6 end-to-end check: exactly one `chore(l10n): push strings` commit per Weblate push).
4. **Broken ICU from a translator.** A translation with bad plural syntax must not reach `main`: Weblate's ICU check flags it (confirmed on the component in Task 2 Step 6), and CI's `flutter gen-l10n` fails on the PR as a backstop.
5. **Vous slipping back.** `test/l10n/french_register_test.dart` keeps running on the Weblate PR through CI (Task 6: required check "Format, analyze, test" runs on the PR head).

- [ ] **Step 3: Write the workflow**

`.github/workflows/weblate-pr.yaml`:
```yaml
# Weblate's translation pull request (branch weblate/l10n), made mergeable: the
# push copy regenerated from the new ARB files, and a Conventional title.
#
# Pushed with the yeet App token: a GITHUB_TOKEN push does not run CI, and main
# requires checks on the head commit. A run with nothing to regenerate commits
# nothing, so the run its own push triggers ends there.
name: Weblate pull request

on:
  pull_request:
    types: [opened, synchronize]

permissions:
  contents: read

concurrency:
  group: weblate-pr
  cancel-in-progress: false

jobs:
  finish:
    name: Push strings and title
    if: >-
      github.head_ref == 'weblate/l10n' &&
      github.event.pull_request.head.repo.full_name == github.repository
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - uses: actions/create-github-app-token@bcd2ba49218906704ab6c1aa796996da409d3eb1 # v3
        id: app
        with:
          client-id: ${{ vars.YEET_APP_ID }}
          private-key: ${{ secrets.YEET_APP_PRIVATE_KEY }}

      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7
        with:
          ref: ${{ github.head_ref }}
          token: ${{ steps.app.outputs.token }}

      - uses: subosito/flutter-action@1a449444c387b1966244ae4d4f8c696479add0b2 # v2
        with:
          flutter-version-file: .fvmrc
          cache: true

      - run: flutter pub get

      - run: dart run tool/push_strings.dart

      - name: Commit push strings
        env:
          GH_TOKEN: ${{ steps.app.outputs.token }}
          BOT: ${{ steps.app.outputs.app-slug }}[bot]
        run: |
          git add android/app/src/main/res/values/push_strings.xml ios/Runner/Localizable.strings
          git diff --cached --quiet && exit 0
          git config user.name "$BOT"
          git config user.email "$(gh api "/users/$BOT" --jq .id)+$BOT@users.noreply.github.com"
          git commit -m 'chore(l10n): push strings'
          git push

      - name: Title
        env:
          GH_TOKEN: ${{ steps.app.outputs.token }}
          PR: ${{ github.event.pull_request.number }}
        run: gh pr edit "$PR" --title 'chore(l10n): sync translations' --add-label l10n
```
If Task 3 Step 1 showed the title is already right, delete the `Title` step, rename the job to `Push strings`, and drop "and a Conventional title" from the header comment.
