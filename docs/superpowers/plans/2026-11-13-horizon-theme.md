# Horizon Theme Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle Loomia to the Horizon direction (gradient hero per screen, floating navigation with a contextual +, quiet white cards), light and dark, phone and desktop, without changing data or flows.

**Architecture:** New tokens on `LoomiaColors` / `AppRadii` and decoration helpers in `AppTheme` (Task 1) feed three shared building blocks: `HeroPanel` + `HeroCard` (Task 3), the restyled cards and `SectionHeader` (Task 2), and the shell's `FloatingNavBar` / `AppSidebar` driven by one route-to-action map (Tasks 4–5). Each feature screen then moves its header into a `HeroPanel` (Tasks 6–12). Previews stay page-level; goldens are regenerated by CI once, at the end (Task 13).

**Tech Stack:** Flutter, `material_ui`, `flutter_riverpod` (no codegen), `go_router`, gen-l10n ARB.

**Spec:** `docs/superpowers/specs/2026-11-13-horizon-theme.md` (issue #499). Visual reference: `docs/design/horizon/*.png`, one per screen, 1× scale, named like the golden it should match.

## Global Constraints

- Branch `feature/499-horizon-theme`; Conventional Commits; PR body `Closes #499`.
- No new dependency. Material from `package:material_ui/material_ui.dart`, imports `package:loomia/...`.
- Widgets never hard-code a colour, radius, font size or spacing: read `Theme.of(context).colorScheme`, `LoomiaColors.of(context)`, `AppSpacing.*`, `AppRadii.*`, `AppTypography.*`. Component styling lives in `lib/app/theme/app_theme.dart`.
- Branch on `context.screenSize` only.
- Copy: English in `lib/l10n/app_en.arb` only, each key with a description; informal register. Only Tasks 4 and 6 touch the ARB (avoids conflicts between parallel tasks).
- Amber `#A75C15` stays `colorScheme.primary` in both modes and stays the only action colour.
- No streaks, scores, ranks or competitive copy anywhere, including the all-done state.
- Never commit goldens rendered locally. Run `git checkout -- test/goldens` before every commit.
- Before claiming a task done: `dart format .`, `flutter analyze` ("No issues found!"), `flutter test`.

## Visual check (every UI task)

Goldens only compare on Linux, so each UI task checks its look locally with the render switch added in Task 1, then throws the PNGs away:

```bash
RENDER_PREVIEWS=1 flutter test test/previews_test.dart --update-goldens --plain-name <golden_name>
# open test/goldens/<golden_name>.png next to docs/design/horizon/<golden_name>.png
git checkout -- test/goldens
```

"Matches" means: same structure, order, colours and corner shapes; spacing within a few px; text may wrap differently (font hinting differs by OS). The mockups show a status bar, device corners and the floating bar; page previews do not.

## Review Focus

- **Long names and French copy in the hero** (a 30-character contact name, FR greetings) must wrap inside the gradient, never overflow or push buttons off-screen. → Task 3 test `hero panel wraps a long title without overflow`, Task 10 test `long contact name wraps in the identity hero`.
- **The floating bar must not cover the last row** of any tab list; content scrolls fully clear of it. → Task 4 test `last row scrolls above the floating bar`.
- **Text-scale 1.3** (accessibility) on the bar: labels fit or the active pill shrinks; no overflow. → Task 4 test `floating bar survives text scale 1.3`.
- **The + always does something on every tab**, including Contacts while picking (bar hidden) and Calendar in 3-days/week mode (uses the selected day). → Task 4 tests `plus on calendar adds on the selected day`, `bar hidden while picking contacts`.
- **Dark mode contrast** of white text on the dark gradient start and of muted chrome labels. → Task 1 tests `white meets AA on both hero starts`, `muted chrome ink meets AA on chrome`.
