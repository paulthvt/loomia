# A time on a task — plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** an optional time on a task; a push at that time (±1 min) on her
phones; from it, postpone by 15 min or 1 h; timed tasks ordered and shown
by time on Today and in the Calendar, in the desktop week's hour grid; the
daily summary counts tasks.
**Architecture:** `task.due_time` (wall clock in the user's zone) and a
claim column `alerted_for`. The existing pg_cron → `send-daily-summary`
Edge Function runs every minute and gains a third job, `taskJob`, beside the
summary and month-end ones. Taps carry their FCM `data`, so a task push
opens that task's sheet.
**Tech Stack:** Flutter, Riverpod (no codegen), Supabase (Postgres, pgTAP,
pg_cron), Deno Edge Function, FCM HTTP v1.
**Spec:** `docs/superpowers/specs/2026-10-26-task-time-design.md`. Figma:
section "Task time — #377" (node 445:14163).

## Global Constraints

- Migration additive only. `supabase db push`, then `supabase functions
  deploy send-daily-summary`, before or with the app release; safe for the
  released app (new columns, enum values, functions; the cron's schedule
  changes, harmless for old apps and the old sender).
- A device gets a kind only if its app lists it in `push_kinds`
  (`device_repository.dart`): new strings ship with the kind.
- No new dependency. No colour, radius, spacing or font size literal.
- Copy in `lib/l10n/app_en.arb` only, every key described. `push*` keys go
  through `dart run tool/push_strings.dart`, outputs committed.
- Goldens through CI only. Issue #377, branch `feature/377-task-time` off
  `origin/main`.

## Rulings made while planning

- **`alerted_for` is cleared by a `before update` trigger** when `due_on`
  or `due_time` is distinct from the old row, so every writer (sheet,
  postpone, an old app moving the day) re-arms without knowing about it.
- **`complete_task` / `delete_task`** (#376) are replaced (`create or
  replace`, same signatures) to copy `due_time`; nothing else changes in them.
- **`claim_daily_summaries` is left alone**; a new
  `claim_daily_summaries_with_tasks()` returns `people` and `tasks` and
  claims when `people + tasks > 0`, and the new sender calls it. The README
  order is `supabase db push`, then `supabase functions deploy`: in between,
  the deployed sender still calls the old function, which must keep
  claiming people only, or a tasks-only user would get "0 people…". The old
  function goes in a later PR.
- **Old app's summary**: a device without `daily_summary_tasks` in
  `push_kinds` gets today's people-only message, and none at all when only
  tasks are due (so it never reads "0 people…").
- **Settings row on first time**: `NotificationsController.ensureFor(zone)`
  creates `NotificationSettings(timeZone: zone)` (summary and month-end
  off) only when there is no row; then `push.ask()`. Called by the sheet
  when it saves a task that gains a time.
- **Postpone time** is a pure `postponed(DateTime now, Duration by)` →
  `(DateTime day, TimeOfDay time)`, rounding `now + by` up to the next whole
  minute; the sheet writes both `dueOn` and `dueTime`.
- **Opening a task from a push**: `Push.opened` becomes
  `Stream<Map<String, Object?>>`; `PushScope` goes to
  `Routes.today` with `?task=<id>` (a new query parameter declared in
  `routes.dart`) for `type: task`, plain `Routes.today` otherwise. Today
  reads it once its tasks have loaded, opens `showTask(editing:)` if the
  task is in the list and open, then clears the parameter.
- **Week grid lanes**: `dayLanes` is generalised to entries with a start and
  end minute (events and timed tasks), so a task at 14:00 and an event at
  14:00 share the column side by side, as two events do.

## Changed while implementing

- **`TaskTime` is a record** (`({int hour, int minute})`), not Flutter's
  `TimeOfDay`, so the domain stays free of widgets; the sheet converts.
- **`set_updated_at` on `task` now fires only on the user's columns**:
  claiming a push writes `alerted_for`, and if that bumped `updated_at`,
  #376's undo would take the next task for edited and keep it.
- **`Job.message` may return null**: an older app gets no summary when only
  tasks are due (its strings can't say it), and the day stays claimed.
- **The daily summary test** pins the new every-minute schedule.
- **Postpone buttons wrap**: side by side they overflowed the 390 px sheet.
- **The push tap** goes through `Routes.todayTask(id)` (`/?task=<id>`);
  Today opens the sheet once the tasks have loaded and clears the address,
  so the same task's next push opens it again.
- **No new Today preview**: its Tasks section is below the golden's frame.
  The Calendar preview gets "Call the supplier" at 14:00 on the 8th.
- **French push strings** fall back to the English ones until Weblate, as
  every new key does.
