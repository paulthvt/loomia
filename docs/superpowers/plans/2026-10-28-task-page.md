# Task page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tapping a task (Today, the Calendar, its push) opens a task page that shows it, with Edit, Delete, the ring and, when its time is near, postpone; on desktop it sits in the Calendar's pane.

**Architecture:** A `TaskView` (stateless, for previews and tests) inside a `TaskPane` (reads the task by id from `tasksProvider`, owns the writes) inside a `TaskPage` (phone), shaped like `EventView` / `EventPane` / `EventPage`. A route `/calendar/task/:id` beside the event's, built by `_calendarPage` like the event's; `openTask` like `openEvent`. Every "open a task" call site switches from `showTask(editing:)` to `openTask`; the form loses postpone and Delete.

**Tech Stack:** Flutter (Riverpod, go_router, material_ui). No data change.

**Spec:** `docs/superpowers/specs/2026-10-28-task-page-design.md` (issue #390). Figma: "Task page — #390", node 465:15232.

## Rulings made while planning

- Path `/calendar/task/:id`: `Routes.taskSegment = 'task/:id'`, `Routes.taskName = 'task'`, `Routes.taskLocation(id)`. The parameter is `id`, like the event's, so the Calendar shell's pane check keeps working; that flag is renamed `eventOpen` → `paneOpen`. The task route is listed before the event's.
- Back: the same `AppBar(leading: BackButton(onPressed: () => backOr(context, Routes.calendar)))` as `EventPage`; the frames' "Back to calendar / Back to Today" is that button's place, no new copy.
- The day line reads `DateFormat.MMMMEEEEd(locale).format(task.dueOn)` ("Thursday, October 22"), beside the ring.
- The bell on the page is an icon after the time (on: `Icons.notifications_active_rounded`; off: `Icons.notifications_off_outlined`), not a button: changing it goes through Edit. Its semantics label reuses `taskAlertOn`/`taskAlertOff`'s meaning through two new keys, `taskAlertIsOn` "Notifies at this time" / `taskAlertIsOff` "Doesn't notify".
- The repeat line reuses `repeatLine(l10n, repeat)` from `task_row.dart`; a done task shows none (as its row).
- After Edit saves, the Calendar selects the saved day (`calendarSelectionProvider.select(saved.dueOn)`), as `_task` did, so a moved task stays in view.
- Postpone and Delete move out of `task_sheet.dart` into `task_page.dart`: the postpone row widget and the delete flow (confirm, or `pickScope(delete: true, task: true)` for a repeating one) move as they are.
- Not found: new keys `taskNotFound` "This task is gone" / `taskNotFoundBody` "It was deleted, maybe on another device." with `Icons.task_alt_rounded`, like the event's.

## Review Focus

- A task deleted on another device while its page is open: the page turns to "not found", no crash (Task 2).
- Ticking a repeating task on the page: the page keeps showing the ticked one (its id), not the next (Task 2).
- Postponing from the page while the save fails: the error shows, the buttons stay (Task 2).
- Today on desktop: a task click lands on the Calendar with the pane, and Back/another day closes it (Task 3).
- A push for a task that is done opens its page; for a deleted one, just Today (Task 3).

## Changes during implementation

- Not found: `taskNotFound` reads "This task isn't in your list any more." and the body reuses `eventNotFoundBody` ("It may have been deleted on another device."), matching the event's page; no `taskNotFoundBody`.
- The ring's tooltips reuse `nextStepMarkDone` / `eventStepUntick`, as the task rows already do.
- The app-level "opened from" tests live in `task_page_test.dart` beside the page's own, rather than in the Today and Calendar test files; the Calendar's view tests already pin that a chip calls `onOpenTask`.
- After a push, the router keeps `/` as its address under the pushed page, so the push test checks the page and that back lands on Today.
