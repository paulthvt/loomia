# Motion — plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the check draws itself and the ticked row waits for it, then slides
out; rows that vanish today slide out; lists animate the rows the user added
or removed; Show/Hide, day change, loading and a few sections stop cutting.
**Architecture:** four small widgets in `lib/core/ui/` carry all of it:
`TickRing` (the drawn check), a hold inside `SlideSwap` (waits for the ring),
`AnimatedRows` (insert/remove in a column), `FadeSwap` (keyed cross-fade).
Callers keep their tick, save and reload code; they only swap widgets.
**Tech Stack:** Flutter, Riverpod (no codegen). No package.
**Spec:** `docs/superpowers/specs/2026-10-27-motion-design.md`.

## Global Constraints

- Durations only through `context.motion(AppMotion.*)`; curves only
  `AppMotion.standard`/`decelerate`/`accelerate`. No raw `Duration` in a widget
  except the 240ms ring threshold, which is `AppMotion.medium`.
- Reduce motion: every movement becomes a 120ms fade (`context.reduceMotion`).
- No new dependency, no migration, no copy change.
- Goldens through CI only; none should change (end states only). A changed
  golden is a bug to explain in the PR.
- Issue #384, branch `feature/384-motion` off `origin/main`, PR `Closes #384`.

## Rulings made while planning

- **`TickRing({required bool selected, VoidCallback? onPressed, String?
  tooltip})`** (`lib/core/ui/tick_ring.dart`), stateful, one
  `AnimationController`. It wraps the existing `IconButton` with
  `AppTheme.resolveRing` (size, padding, tap target, ring and fill stay the
  theme's), and replaces only the icon: the ghost `Icons.check_rounded`
  while not selected, a `_CheckPainter(progress)` while selected.
  `selected` false → true: forward over `AppMotion.medium`, `decelerate`.
  true → false while mounted: reverse over `AppMotion.fast`. First build
  with `selected: true` (a crossed-out task, a row rebuilt mid-tick): drawn,
  no animation. Reduce motion: the painter is drawn whole and faded in/out
  over `AppMotion.fast`.
- **Painter:** the `check_rounded` path in an 18px box, two strokes (short
  from (4.5, 9.5) to (7.5, 12.5), long to (13.5, 6)), `StrokeCap.round`,
  `StrokeJoin.round`, width 2, colour from `IconTheme.of(context).color`
  (the button's `onPrimary`). `PathMetric.extractPath(0, length * progress)`
  across both strokes as one path.
- **Hold:** `SlideSwap` becomes stateful and provides a `TickHold` (a small
  `InheritedWidget` over a `ValueNotifier<Duration?>` "ring started at",
  read from a `Stopwatch` owned by the slot). `TickRing` calls
  `TickHold.maybeOf(context)?.start()` when it starts drawing. When
  `SlideSwap`'s child leaves or changes key, it keeps showing the previous
  child until `AppMotion.medium` has passed since that start (a `Timer` for
  the rest, zero if already passed or no ring started), then hands the new
  child to its `AnimatedSwitcher`. Reduce motion: the hold is
  `AppMotion.fast`. No caller passes anything.
- **Event steps on Today** get a busy set like people rows: `_busySteps`
  in `_TodayPageState`, added before `events.tick`, removed in `finally`;
  passed to `todayEventItems(busySteps:)` as `Set<String>` of
  `'${event.id}:${step.id}'`.
- **`AnimatedRows({required List<Widget> children, double spacing = 0,
  Duration delay = Duration.zero})`** (`lib/core/ui/animated_rows.dart`):
  a `Column` whose children must have distinct keys. First build: as a
  `Column`, no animation. Later builds: a new key grows in (`SizeTransition`
  + fade, `AppMotion.medium`, `decelerate`); a gone key stays at its old
  index and folds out (`accelerate`), then is dropped. Both start after
  [delay]. The gap above a row is part of its slot, so it opens and closes
  with it. Not `AnimatedList`: every call site is a `Column` or `ListView`
  `children`, not a scrollable of its own.
- **History** passes `delay: context.motion(AppMotion.slow)`: the sheet or
  confirm dialog is closing for that long, so the entry moves once it's
  gone. `AnimatedRows` is keyed by `_expanded`, so "See all" builds a new
  one: the extra entries appear at once.
- **`FadeSwap({required Widget child, required Duration duration})`**
  (`lib/core/ui/fade_swap.dart`): `AnimatedSwitcher` with
  `context.motion(duration)`, `decelerate` in, `accelerate` out, and the
  outgoing child laid over the top (same `layoutBuilder` as `SlideSwap`),
  inside an `AnimatedSize` (`standard`) so the height eases. Keyed by the
  child's key.
- **Today all done:** the spec says the done state fades in after the last
  row's slide. The last row's list leaves the tree when the branch switches
  to `_allDone`, so it can't slide. Instead the branch (due list vs all done
  vs up to date) goes through `FadeSwap(AppMotion.slow)`, keyed by branch:
  the last row, check drawn (the hold still applies, inside its slot),
  fades out with its list while the done state fades in.
- **Contacts list:** `AnimatedRows` keyed by `(stage, tags, query)`, so a
  filter or search change is a new list shown at once. A stage or tag chip
  change also goes through `FadeSwap(AppMotion.quick)` keyed by
  `(stage, tags)`; typing in search doesn't fade.
- **Loading → content:** a branch qualifies when a centred
  `CircularProgressIndicator` is replaced by the content in the same place.
  It goes through `FadeSwap(AppMotion.quick)`. A spinner inside a button or
  a row (`submit_button`, the 20px one in `next_step_section`) doesn't.

## Review Focus

- **A row deleted elsewhere** (another device, a reload) while no ring was
  tapped: it must leave with no hold. Test in Task 2.
- **Undo while the row is still held** (tap Undo within 240ms of the tick):
  the row comes back without a flicker of slide-out. Test in Task 2.
- **A failed save** after the check finished drawing: the ring un-draws, the
  row stays, the snackbar shows. Test in Task 1 (ring) and Task 3 (event step).
- **Pull to refresh** on Today, History and Contacts: rows appear at once, no
  wave of inserts. Test in Task 4 (`AnimatedRows` keeps the old rows when the
  keys are the same; a refresh with the same ids animates nothing).
- **Reduce motion** across the four widgets: a 120ms fade, nothing that
  slides or grows. One test per widget, in its task.

## Changes during implementation

- **One hold for both slots.** The hold is a `HoldsForTick` mixin in
  `slide_swap.dart`, used by `SlideSwap` and `FadeSwap`. A ring attaches to
  every enclosing slot, so a section that disappears with its last row (Today's
  EVENTS, Today's due list going to "all done") also waits for the check.
- **Today's EVENTS block** goes through `FadeSwap(slow)` as a whole, so the
  last step ticked fades out with its header after its check is drawn. Its rows
  are an `AnimatedRows(slideOut: true)`: a step that leaves while others stay
  slides out, as people rows do.
- **Event steps on Today** reuse `_busy` with `stepKey(due)` as the key,
  instead of a second set.
- **`AnimatedRows`** gained `gap` (`RowGap.between/above/below`) for the
  contact reminders before and after the step, and `slideOut` for Today's
  events and the reminders. Its delay is part of the row's animation
  (`Interval`), not a timer, so `pumpAndSettle` covers it.
- **`FadeSwap`** doesn't cross-fade: the new child is in place at once and
  the old one fades out on top (and ignores taps). Content both share (the goal
  line, a header) never dims.
- **`FoldBody`** (`check_in_items.dart`): the Show/Hide body shared by Catch up
  and the Calendar's People block.
- **Not done:**
  - Tags and workflows settings lists: their rows sit in `SettingsGroup`, which
    lays them out as a Material list group, and they change rarely.
  - The workflow timeline's Mark done keeps its plain check icon: it isn't a
    tick ring, and making it one would change how the page looks. Its
    current-step wash now moves with `AnimatedContainer`.
  - Loading fades on full-page spinners (contact page, event page, goals,
    editors): only the contacts list, History and Today fade from their
    spinner.
- **Tests that waited one frame** for a change now wait for the fade (the
  history Retry test).
- **Not checked on a device:** the timing was checked with widget tests only,
  with Flutter 3.47.0 rather than the pinned 3.47.7.
