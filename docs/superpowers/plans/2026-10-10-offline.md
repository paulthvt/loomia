# Offline state Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When the backend can't be reached, every load failure says "You're offline" with Try again. Any other failure keeps its "Couldn't load …" title and no longer blames the connection. Offline Storage and Functions errors are recognised as network, and offline photo cleanup stops reaching Sentry (#46).

**Architecture:** `PeopleFailure.network` / `AuthFailure.network` stay the only offline signal. The mappings learn two more shapes. One `LoadFailed` widget in `core/ui/` takes `offline: bool` and replaces every full-size load error. Inline rows swap their text.

**Tech Stack:** Flutter (`material_ui`), `flutter_riverpod` 3, `supabase_flutter` 2.18.

**Spec:** `docs/superpowers/specs/2026-10-10-offline-design.md`. No Figma (reuses `EmptyState`).

## Global Constraints

- **Dart imports:** `package:loomia/...`; Material from `package:material_ui/material_ui.dart`.
- **Copy:** English only in `lib/l10n/app_en.arb`, every key with a description, then `flutter gen-l10n`.
- **Quality gate per task:** `dart format .`, `flutter analyze` ("No issues found!"), `flutter test`. Goldens come from CI only.
- **Branch:** `feature/46-offline-state` off `main`. The PR body says `Closes #46`. Stage changed files by path; the user keeps untracked local files (`pubspec.lock` change included).

## Rulings made while planning

- **`storageUnreachable` lives in `photo_repository.dart`.** It's the only Storage client. `peopleFailureFrom` (features) may import core; `core/` must not import features.
- **A `StorageException` without `statusCode` is a refusal.** The existing test `StorageException('Payload too large')` → unknown stays true. Only a non-numeric `statusCode` (storage_client puts the error's runtime type there) is network.
- **Tests that used `PeopleFailure.network` to reach "Couldn't load …"** now assert the offline copy, which is what that failure means. Today gets one `PeopleFailure.unknown` test for the other branch.
- **`workflow_timeline_page`'s `_Gone` for a failed workflows load** becomes `LoadFailed` too. `_Gone` stays for its other three states.
- **No previews change:** no `@Preview` shows a load error, so no golden regenerates.
