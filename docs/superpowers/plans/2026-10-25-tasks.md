# Tasks — plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a task (title, due day, optional note, about nobody) on Today in
its own section and in the Calendar on its day; tick, untick, edit, delete.
**Architecture:** one table `task`, read whole like events. New feature
`lib/features/tasks/` (domain, data, presentation) with an account-keyed
`tasksProvider`. Today and the Calendar take the list as a plain parameter
of their views (`TodayView`, `CalendarView`), so previews and widget tests
pass it in without providers.
**Tech Stack:** Flutter, Riverpod (no codegen), Supabase (Postgres, pgTAP).
**Spec:** `docs/superpowers/specs/2026-10-25-tasks-design.md`. Figma: section
"Tasks — #375" (node 430:13589).

## Global Constraints

- Migration additive only: new table, nothing else changes. `supabase db push`
  before the app release.
- No new dependency. No colour, radius, spacing or font size literal in a
  widget.
- Copy in `lib/l10n/app_en.arb` only, every key with a description, informal
  register. No string concatenation of translated pieces: one key per
  sentence.
- `package:material_ui/material_ui.dart`, `package:loomia/...` imports.
- Every `@Preview` touched gets its golden regenerated through CI (README →
  Golden tests), never locally.
- Issue #375, branch `feature/375-tasks` off `main`.

## Rulings made while planning

- `Task.key` is `'task:<id>'`, so Today's `_busy` set (keyed by `Due.key`)
  holds tasks too without a clash.
- Today's done count: `doneTodayProvider` is left alone (it counts history
  entries, tasks write none). The hero adds tasks with `doneOn == today` from
  the loaded list: `done = doneToday + tasksDoneToday`,
  `total = done + due.length + todayTasks.length`.
- "Priority" becomes a new key `todaySectionPeople`; `todaySectionPriority` is
  deleted, so French shows English until Weblate translates it instead of the
  stale "Priorité".
- The task sheet reuses `ReminderDayField` (`reminder_sheet.dart`) and
  `LoomiaDialog.show`: a sheet on mobile, a dialog elsewhere, as reminders.
  Delete goes through `confirmDestructive`, as an event's delete.
- Ticking from the Calendar uses the same `offerUndo`; unticking a crossed-out
  task is one write with no snackbar.
- A failed tasks load: Today's Tasks section shows `LoadFailed` with Try again
  in place of its rows; the Calendar shows the events and no task rows (the
  events error path already covers a full failure).
- The desktop hour-grid week gets a strip under each `_ColumnHeader`: that
  day's tasks as `MonthTaskChip`s, the strip as tall as the busiest day,
  nothing when the week has no task.

## Review Focus

1. Day boundaries: `due_on` / `done_on` are dates read with `DateTime.parse`
   to local midnight; a task due today shows today, one due tomorrow does not,
   in any time zone (test in Task 2 with a UTC+14 and a UTC−10 `today`).
2. Blank or whitespace-only title: refused by the form and by the server's
   check; a title is stored trimmed (Tasks 1 and 3).
3. Two quick taps on one ring write once (busy key), and a tick then Undo
   then tick again ends ticked (Task 4).
4. Undo after the task was deleted (another tab, or deleted while the
   snackbar shows): no crash, no task comes back (Tasks 2 and 4).
5. A long title or note: one line in the Calendar's month cell and two in
   rows, ellipsised; the sheet's note field grows (Tasks 5 and 6).

**Interfaces:**
- Produces:
  - `class Task { final String id; final String title; final String? note; final DateTime dueOn; final DateTime? doneOn; bool get done; String get key; }` (`key` = `'task:$id'`; days are local midnights).
  - `typedef TaskDraft = ({String title, String? note, DateTime dueOn});`
  - `List<Task> todayTasks(List<Task> tasks, DateTime today)` — open, `dueOn` on or before today, oldest `dueOn` first, then `createdAt`. `Task` therefore also carries `final DateTime createdAt`.
  - `List<Task> tasksOn(List<Task> tasks, DateTime day)` — every task due that day, open first, then creation order.
  - `Map<DateTime, int> openTasksPerDay(List<Task> tasks)` — open tasks only.
  - `class TaskRepository { Future<List<Task>> list(); Future<Task> add(TaskDraft draft); Future<Task> update(String id, TaskDraft draft); Future<Task?> setDone(String id, DateTime? on); Future<void> delete(String id); }` — every method through `guardPeople`, days through `dayColumn`; `setDone` returns null when the row is gone. `taskRepositoryProvider`.
  - `tasksProvider` — `AsyncNotifierProvider.family<TasksController, List<Task>, String?>` keyed by account email, `retry: (error, _) => null`, empty when signed out; methods `add(TaskDraft)`, `save(String id, TaskDraft)`, `setDone(Task task, DateTime? on)`, `remove(String id)`. Each writes, then puts the result into the state (gone from the server: removed from the state). Throws `PeopleFailure`; state unchanged on failure.
